# Decisions

Newest at the bottom. Each entry: what was chosen, over what, and why.

## Monorepo replacing the per-app repos (2026-10-17)

`auth-service`, `vps-edge`, `pokemon_cards`, `workout` and `media` are merged into this one repo, with a single backend, a single frontend workspace and a single database. Chosen over keeping separate repos because every app already shared the same stack, conventions and deploy target, and changes that crossed repos (auth header contract, CORS lists, nginx blocks, backups) had to be made in up to five places. **No git history is carried over**: the old repos stay as archives.

## Backend: FastAPI, Python 3.14, uv, SQLAlchemy 2.1 + psycopg 3 (2026-10-17)

Same framework as every old app. The baseline is `media`'s backend (the newest): `core/` + `domains/` layout, SQLAlchemy 2.1, psycopg 3 (`postgresql+psycopg://` URLs) rather than psycopg2. Settings use `pydantic-settings` (env vars, typed defaults). `uv` for everything Python. The test client uses `httpx2` (Starlette deprecated `httpx`).

**Connection pool: 10 + 30 overflow, no connection held across slow work (2026-10-19).** Every app shares one engine. With FastAPI's default `"request"` scope, `get_db` closes only after the response is fully sent, so a `FileResponse` held a pooled connection for the whole download; a public share page's thumbnail grid exhausted SQLAlchemy's default 5 + 10 and 500'd every app for 30 s (`QueuePool limit … reached`). The card file routes now close their session when the endpoint returns (`Depends(get_db, scope="function")` on the public share routes, an explicit `db.close()` on `/images/`, whose session comes from `require_app`). The same rule covers everything else that waits on something slow: the admin images export (streamed zip) and import (upload) close the admin check's session first; media search and add-from-search close it before calling TMDB / Open Library (the cover is fetched before the insert); the catalog refresh's scan downloads, TCGdex details and thumbnail generation end their read transaction before the network or resizing work and write in short per-set / per-batch transactions; `make media-refresh` keeps its items loaded across commits (`expire_on_commit=False`). The pool grew to 10 + 30: one connection per thread of Starlette's 40 running sync endpoints (more would never be used), well under Postgres' 100 connections so migrations, backups and `psql` still get one. Chosen over only raising the pool (any slow download would still hold a connection) and over moving every route to `"function"` scope (a change to every endpoint, while only these routes hold a connection long).

## One database, one schema per app (2026-10-17)

One Postgres database with schemas `core`, `portfolio`, `workout`, `cards`, `media`, one Alembic history for all of them (`alembic_version` in `core`). Chosen over:
- one database per app (the old setup): you can't have a real foreign key to a shared `users` table, and you get five backups and five migration histories;
- all tables mixed in `public`: no namespacing, and name clashes (`tags`, `projects`) between apps.

Each app's tables stay grouped, readable and droppable on their own, and `core.users` is a real FK target for everyone.

## Auth verified by the backend, not the proxy (2026-10-17)

The backend checks the session cookie itself through a FastAPI dependency. The old flow is removed: nginx `auth_request` to `auth-service`'s `/internal/validate`, then `X-User-*` headers, then a per-app shadow `users` row. With one backend there is no separate service to ask, and a dependency is testable and visible in the code, where the old check was hidden in proxy config. The dependencies are `get_current_user`, `get_optional_user`, `require_admin` and `require_app` in `core/deps.py`; see architecture.md "Session".

## API exposed as `/api` on every host, not `api.alanbignon.com` (2026-10-17)

Every host's nginx server block proxies `/api/` to the same backend, and the frontend uses relative `/api/...` URLs. Chosen over a dedicated `api.alanbignon.com` because same-origin calls need no CORS configuration, no preflight `OPTIONS` round-trips and no `withCredentials`, and dev (Angular dev-server proxy) behaves exactly like prod. Backend routes are namespaced by domain (`/api/cards/...`), so it doesn't matter which host a request arrives on. An `api.` host can still be added later as an extra entry point (e.g. for a mobile client) without changing anything.

## Frontend: one Angular CLI workspace, one application per site (2026-10-17)

`frontend/` is a single Angular 22 workspace with a `shared` library and five applications (`portfolio`, `workout`, `cards`, `media`, `auth`), each building its own bundle served on its own host. Chosen over one single application that switches routes by `window.location.hostname`, because each site needs its own `index.html` title/meta, favicon, PWA manifest and service worker, and the public portfolio may want prerendering on its own. A single app would have to fake all of that at runtime and couple every site's routing together. A shared `node_modules` and `package.json` still give one Angular version and one upgrade for all.

## Plain Angular CLI, not Nx (2026-10-17)

Nx adds affected-only builds, caching and boundary lint rules, but replaces `angular.json` with its own config, has its own upgrade cadence, and is one more layer to debug. With one developer, five small apps and esbuild builds that take seconds, it doesn't pay for itself. `nx init` can be added onto a plain workspace later if that changes.

## `@shared` consumed from source (2026-10-17)

`tsconfig.json` maps `@shared` to `projects/shared/src/public-api.ts` instead of the generator's default `dist/shared`, so apps compile the library's source directly: no `ng build shared` before serving or building an app, and edits show up live in `ng serve`. The library keeps its own `ng test shared` target. It would only need to be built with ng-packagr if it were ever published as a package.

## One edge nginx replacing vps-edge and per-app frontend nginx (2026-10-17)

`infra/nginx` is the only proxy. It terminates TLS, serves every app's static bundle (built into its image by a multi-stage Dockerfile) by `Host`, and proxies `/api` to the backend. Previously a request crossed two nginx hops (vps-edge, then each app's own frontend nginx) over an external `edge_net` network. That existed only because independent stacks couldn't share ports 80/443, which no longer applies. `resolver 127.0.0.11` with a variable upstream lets the edge start even when the backend isn't up.

## One multi-SAN TLS certificate (2026-10-17)

One Let's Encrypt cert covering every hostname, at `infra/ssl/alanbignon.com/`, referenced once from `snippets/tls.conf`. The old box already used a multi-SAN cert but copied it into one directory per domain; a single path removes that duplication. See `deployment.md`.

## Postgres 18, Node 24 (2026-10-17)

The new database starts on Postgres 18. The old stacks were on 16, but since data moves via the apps' export/import rather than `pg_dump`, there's no version constraint. Volumes mount `/var/lib/postgresql`, as the 18 image expects. Node 24 (current LTS) runs in every frontend container. Angular CLI 22 needs at least Node 22.22, newer than the host's 22.16, so `ng` commands run in the container (`docker compose exec frontend npx ng …`).

## No production data migration (2026-10-17)

Old data is not copied database-to-database. Workout and cards already have export/import features, which get ported with their apps and are used to reload data after cutover. Media data is re-entered or gets an import later, and auth accounts are recreated. This avoids writing one-off migration scripts across differently-shaped schemas.

## Auth libraries: PyJWT + pwdlib (argon2), not python-jose + passlib (2026-10-17)

auth-service used `python-jose` and `passlib[bcrypt]`, with `bcrypt` pinned to 3.2.2 because passlib breaks on newer bcrypt. Both are effectively unmaintained. PyJWT is maintained and does everything needed here (HS256, `exp`/`nbf`/`iss`/`aud` checks, required claims). pwdlib is the maintained successor to passlib, by the FastAPI user-auth authors, and its recommended hasher is argon2id. No password hashes are carried over (accounts are recreated, see "No production data migration"), so there was no reason to stay on bcrypt.

## Session: httpOnly JWT cookies + double-submit CSRF, as before (2026-10-17)

Kept from auth-service, over a `Authorization: Bearer` token in localStorage, because httpOnly cookies can't be read by injected JS, and one cookie on `.alanbignon.com` logs the user into every app with no SSO redirect dance. Changes from auth-service:
- Cookies renamed `session` / `refresh` / `csrf` (were `auth_token` / `refresh_token` / `csrf_token`).
- Lifetimes 15 min access / 30 days refresh (refresh was 7 days), so a monthly visit is enough to stay logged in.
- `refresh` has `Path=/api/auth`, so the long-lived token is only sent to the two endpoints that use it.
- The `session` cookie lives as long as the refresh token, longer than the JWT inside it. An expired token still reaches the backend, which answers 401 and makes the frontend refresh. With a cookie dying with its token, `get_optional_user` would silently treat a logged-in user as anonymous on public routes.
- A session cookie that is present but invalid gives 401 even on `get_optional_user` routes, for the same reason.
- `Domain`/`Secure` come from `COOKIE_DOMAIN`/`COOKIE_SECURE`. Dev: no Domain, so cookies are host-only on `localhost` and shared by every port. Prod: `.alanbignon.com` and Secure. `SameSite=Lax` everywhere.
- The backend refuses to start without `SECRET_KEY` (≥ 32 chars) and `REGISTER_SECRET` (≥ 16 chars). Dev compose sets fixed fake ones, and prod reads them from `.env`.
- JWT `iss`/`aud` are fixed to `alanbignon.com`. Dev and prod are told apart by their different secrets.

## Invite-only sign-up kept; no dev auth bypass, `make seed-user` instead (2026-10-17)

`POST /api/auth/register` still needs the `REGISTER_SECRET` as `X-Register-Secret`: the site has one real user, and open sign-up would only attract spam accounts. Other apps don't get a `REQUIRE_AUTH=false`-style bypass for dev. A dev bypass is one more code path that could end up enabled in prod, and it hides real auth bugs. Instead, `make seed-user` creates or updates an admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD`/`ADMIN_PSEUDO` (dev defaults in compose), and `make prod-seed-user` does the same in prod. It's also the only way to set `is_admin`.

## Rate limiting: slowapi, on login and register only (2026-10-17)

Same library as auth-service (in-memory, per client IP, one uvicorn worker in prod). Only the endpoints worth brute-forcing are limited: login 10/minute, register 20/hour. auth-service also limited every endpoint plus a 120/minute default, which mostly risked throttling the user's own refresh/me calls. `core/rate_limit.py` is shared, so another domain can limit a route with `@limiter.limit(...)`.

## Frontend environment: one shared pair of environment files (2026-10-17)

App URLs (the login page for guards, the portfolio as the default post-login target, links on the account page) and the prod/dev redirect rule come from `projects/shared/src/lib/environment/environment{,.development}.ts`, swapped per build by `fileReplacements`, read through an `ENVIRONMENT` token. Chosen over deriving them from `window.location.hostname` at runtime because the build states which URLs it targets. One pair in `@shared` rather than one per app, because every app needs the same URLs.

## i18n: ngx-translate in `@shared`, translations bundled (2026-10-17)

Same library as auth-service. `provideI18n({ en, fr })` from `@shared` sets it up with the app's own JSON files imported into the bundle (a static loader, no HTTP fetch for translations). `LanguageService` follows the logged-in user's `language`; logged out, it uses the last language used on that site (localStorage), then the browser's, then French.

## Portfolio: hand-written projects, bilingual descriptions, free-text tags (2026-10-17)

Projects are created and edited by users with the `portfolio` app (and admins), through `require_app("portfolio")` routes (was `require_admin`, see "Per-user app access"). There is no GitHub sync, and nothing is imported from workout's `projects` table. Changes from workout's version:
- **No `user_id`**: workout scoped projects per user and picked the "portfolio user" from an env var. There is now one portfolio, and write access is decided by the `portfolio` grant.
- **Bilingual descriptions**: `description_fr` and `description_en` columns, both required, shown by the UI language. Chosen over one free-language column because the site is FR/EN everywhere else. The name isn't translated, since it's a proper noun.
- **`repo_url` over `github_link`**: any `https://` URL, not only `github.com`, so a project hosted on another forge can be linked.
- **`featured` + `position`**: the order is `position` only (manual). `featured` only highlights a card. Chosen over "featured first" so there is one ordering rule.
- **Tags**: free text, created on the fly, reused case-insensitively (workout matched case-sensitively), and deleted once unused. There is no tag admin page and no colours, so the form needs nothing more than a comma-separated field.
- **Public routes take no auth dependency**: the list doesn't change with the viewer (admin buttons are a frontend concern), so there is no `get_optional_user`, and a stale session cookie can't turn a public read into a 401.
- **Cards only**: no detail page or slug. `GET /projects/{id}` exists for the admin form.

## Shared header in `@shared`, with its strings shipped by `provideI18n` (2026-10-17)

The top bar (title, app links slot, FR/EN switch, login or account link) is an `@shared` component, `ab-header`, because every app except auth needs the same one. Its few strings live in `@shared` under a `SHARED` key that `provideI18n` merges into each app's translations. Chosen over asking every app to copy the header keys into its own JSON. Only `portfolio` uses it in this step; the other apps adopt it when they are ported. The header links logged-in users to the auth app's account page rather than offering a logout button, so account actions (pseudo, language, logout) stay in one place. `httpStatus` (error → HTTP status) also moved from the auth app to `@shared`, since portfolio needs it too.

## Per-user app access in `core.user_apps`, managed from the auth app (2026-10-17)

Each account starts with access to no app. An admin grants `workout`, `cards`, `media` or `portfolio` per user on the auth app's `/admin/users` page. Choices:
- **A `core.user_apps` join table** (user, app) over an array column on `users` or per-app tables: one row per grant, a check constraint on the app name, and `ON DELETE CASCADE` with the user. It lives in `core` because every app reads it.
- **Admins bypass**: `is_admin` implies every app, so the admin can't lock themselves out and needs no rows. `/api/auth/me` returns the *effective* list (`apps`), so the frontend has one thing to check.
- **Portfolio stays public**: its grant means "may edit projects", replacing the `is_admin` check on its write routes.
- **Enforced on both sides**: `require_app("<app>")` in `core/deps.py` (403 without access) on each app's routes, and `appGuard(app)` in `@shared` on each app's pages. A logged-in user without access is sent to the auth app's account page, which lists only the apps they can open. Chosen over a "no access" page in each app because the account page already is the hub of apps.
- Still only `make seed-user` sets `is_admin`; the users page doesn't toggle it or delete accounts (see ideas.md).

## Media: ported from `media` with its data model, sources and covers (2026-10-17)

`media` was already on this stack, so its `domains/media` was adapted rather than rewritten. What changed:
- **Auth**: `core.deps.require_app("media")` (a session, the `media` grant or admin, and CSRF on unsafe routes) replaces the `X-User-*` headers, the `REQUIRE_AUTH=false` dev bypass, the CORS setup and the `users` shadow table. `library_entries.user_id` and `media_items.created_by_user_id` reference `core.users.id`. Every user with access to media has their own library over the shared catalog.
- **Routes** moved under `/api/media/...`. The cover route became `/api/media/items/{id}/cover` (was `/api/media/{id}/cover`). `/api/dashboard` (unused since media's home page was removed) and `/api/users/me` (replaced by `/api/auth/me`) are dropped.
- **No share links**: media had none yet (only an idea, which is why its docs reserved `/api/public/`). They stay in ideas.md.
- **Kept as-is**: the shared catalog + per-user `library_entries` + `reading_sessions` model, the status rules, TMDB (films, series) and Open Library (books) as metadata sources called only by the backend, covers cached in Postgres (`bytea`, so the one database backup includes them), and EN + FR titles/synopses in the catalog. One fresh migration; media's own history is not carried over, and no rows are imported (see "No production data migration").
- **HTTP client**: `httpx2`, already used by the test client, is now also a runtime dependency for the source calls (media used `httpx`, which Starlette deprecated). Tests swap its transport for an `httpx2.MockTransport` that fails on any unregistered URL.
- **TMDB token**: `TMDB_READ_ACCESS_TOKEN` in `core/config.py`, from `.env` in dev and prod. Without it, film and series search answer 502 and books still work. Tests never use a real token.
- **Metadata refresh**: media's `scripts/refresh_metadata.py` became `domains/media/refresh.py`, run with `make media-refresh` / `make prod-media-refresh`.
- **Frontend**: the app uses `@shared`'s `authGuard`, `AuthService`, `LanguageService` (so the header's FR/EN switch now also changes titles, which media couldn't do) and `ab-header`, instead of its own copies. Only the inline-SVG icon component moved to `@shared` (as `ab-icon`); labels, API wrappers, poster, rating and quick actions stay in the media app, since no other app uses them.
- **Look**: "library paper" (cream paper, ink text, Fraunces serif headings, oxblood accent), deliberately unlike portfolio (dark/lime) and auth (neo-brutalist). Films and series get their own accents (teal, ochre) so the app doesn't read as books-only. It replaces media's light indigo look, which matched pokemon_cards.

## Workout: ported from `workout` onto this stack (2026-10-18)

`workout` was on FastAPI 0.115, SQLAlchemy 2.0 with `Column` models, psycopg2, structlog and Angular 21 with RxJS services and `ChangeDetectorRef`. Its features were kept and its code rewritten onto this repo's patterns (`domains/workout`, Mapped models, psycopg 3, stdlib `logging`, standalone zoneless Angular 22 with signals, Vitest). What changed:
- **Auth**: `require_app("workout")` (CSRF on unsafe routes) and `require_admin` replace the `X-User-*` headers, the `REQUIRE_AUTH=false` dev user, CORS and the `users` shadow table (with its `is_admin`/`pseudo`/`language` copies). Rows reference `core.users.id`. `/api/users` became `/api/workout/users` (only workout users).
- **Read-only sharing kept, anonymous access dropped**: the old app showed the first user's workouts and dashboard to anonymous visitors and let anyone pick any user. Now only workout users see each other, read-only: workouts, stats and templates (plus copying a template), not saved circuits or live sessions. Chosen over strictly private data because the app's users (a couple training together) compare progress.
- **Catalog permissions**: shared catalog as before, but editing and deleting exercises/equipments is admin-only (any user could before), so one user can't rename or remove what another's history uses. Adding stays open to every workout user. Deleting an exercise is refused while a workout, template **or saved circuit** uses it (the old check forgot saved circuits).
- **No `muscles` table**: the 16 muscles were already a fixed list in code (the body map's SVG ids); `exercise_muscles.muscle` is a text column with a check constraint.
- **Stats computed server-side** (`GET /api/workout/stats`) instead of the browser fetching every workout of the range 100 at a time: a small payload, and the aggregation rules (volume, Epley 1RM, weeks, muscles) are tested in pytest. The browser only lays out the calendar and charts.
- **Live session routes** are `/api/workout/session/...` without a workout id (there is at most one per user, enforced by a partial unique index, where the old app only checked in code). Finish takes the browser's local date, so a session after midnight UTC isn't dated the day before. Checked sets are also kept in `localStorage`, so reloading mid-session no longer loses them (finish deletes unchecked sets).
- **Import/export**: was admin-only (multi-user files) in the UI. Now every user imports/exports their own workouts, templates and saved circuits (new) on `/data`, in the old per-user file shapes; the admin page keeps the multi-user files (matched to `core.users` by email, used to reload prod at cutover; saved circuits get one too, `[{user_email, circuits}]`), catalog files and delete-all buttons. Re-importing no longer duplicates: identical workouts and already-used template/circuit names are skipped and reported. Old exports, including `strength`/`cardio` entries, import as-is.
- **No automatic catalog seed**: the catalog is loaded through the admin import (`data/*.json` from the old repo, or a prod export), chosen over a migration or a seed command so there is one path for catalog data and no copy of it in this repo.
- **Names**: exercise and equipment names unique case-insensitively (was exact), template and saved-circuit names unique per user (were free), so imports can match by name.
- **Dropped**: the `projects`/`tags` tables and pages (the portfolio replaced them), the home page (moved to the portfolio), the users table on the admin page (now the auth app's `/admin/users`), the service worker (see ideas.md), server-side exercise/equipment pagination and filters (the catalog is ~150 rows, filtered in the browser), structlog and the request-logging/security-header middlewares.
- **Frontend**: `@shared`'s `AuthService`, `appGuard`/`adminGuard`, `LanguageService`, `ab-header` and `ab-icon`. The old helpers (duration/distance formatting, muscle body map + SVG cache, equipment selector, import-export section) stay in the workout app, since no other app uses them. One entries editor component now serves the workout, template and saved-circuit forms (the old app had four copies). The muscle-map SVGs and the "AB" PWA icons are carried over.
- **Look**: "old style, modernised": the old app's warm grey and rose-brown kept, made more polished (Manrope, white cards with soft warm shadows, pill controls, round calendar days), following the system light/dark setting. Unlike portfolio (dark/lime), auth (neo-brutalist) and media (cream paper, serif). The port first shipped a "scoreboard" look (navy, signal orange, condensed numerals). It was replaced on 2026-10-18, after comparing a dozen directions on the dashboard, because it felt like a generic dark sports app and the old colours were what the user wanted back, only more premium.

## Backend tests: parallel with pytest-xdist, cheap argon2 (2026-10-18)

`pytest` runs with `-n auto` (pytest-xdist, set in `pyproject.toml` `addopts`), and every worker gets its own database `website_test_gw<N>`, created on the fly, because the autouse cleanup wipes every table after each test. Tests replace `core.security._password_hash` with argon2 at `time_cost=1, memory_cost=1024`: the recommended parameters cost ~60 ms per test user (hash + login), nearly half the serial run. Together they take the suite from ~85 s to ~10 s. The production parameters are unchanged. `-n 0` runs serially (for `pdb`, or to read output in order).

## Cards: port plan for `pokemon_cards` (2026-10-18)

The biggest app (≈18k lines of Python, 11k of TypeScript, 1.9 GB of images), ported in one step. Choices:
- **Auth**: `require_app("cards")` on every route except the public share routes; catalog admin (refresh, imports, name fix) uses `core`'s `require_admin` instead of the old local `users.is_admin`. No shadow `users` table, no `X-User-*` headers, no `REQUIRE_AUTH=false` bypass, no CORS. Every user FK (`cards`, `decks`, `collection_history`, `purchases`, `set_shares`, `shopping_lists`, the combat players) points at `core.users.id`. Card name/image language comes from the current user's `core.users.language`.
- **Card Scan dropped for now**: torch + open_clip would add 1–2 GB to the backend image for one feature. The Scan page, `/api/scan/identify`, the `image_embedding(_fr)` columns, the embeddings import/export and the `update_embeddings` refresh step are not ported (ideas.md). Chosen over a separate ML container or torch in the backend.
- **Images on a volume, served by the backend**: a `cards_data` volume (`CARDS_DATA_DIR`), same layout as the old `backend/data/`, so collection exports still match by `image_path`. `GET /api/cards/images/{path}` returns the file behind `require_app("cards")` (path kept inside the root), with `Cache-Control: private` and a long max-age. Chosen over nginx `X-Accel-Redirect` (dev has no nginx, so it would need two code paths) and over `bytea` in Postgres like media covers (1.9 GB in every dump). This replaces the old unauthenticated `/card-images/` mount, which only the edge's `auth_request` protected.
- **Catalog source in the repo, refresh pipeline ported**: `DATA/` (42 MB of saved pokecardex HTML) is copied to `backend/domains/cards/source/` (`CARDS_SOURCE_DIR`) and the refresh steps are ported, so new sets can still be added once the old repo is archived. The first load uses the old app's catalog and image exports rather than re-downloading everything. Refresh job progress stays in memory (background thread + polling), which works because the backend runs one process.
- **Outbound calls**: the refresh downloads scans/logos/variant badges from pokecardex's CDN and card text from TCGdex. Admin-triggered only, never while browsing. Done with `httpx2` (as in media) instead of `requests`.
- **Frontend rewritten**, as workout was: standalone zoneless Angular 22 with signals instead of zone.js + RxJS services, and `@shared`'s `AuthService`, `appGuard`/`adminGuard`, `LanguageService`, `ab-header` and `ab-icon` instead of its own auth/translate setup. Cards-only helpers (filters, set grid, variant display, rarity categories, sort, deck visuals) stay in the cards app.
- **Public share links kept**: `/api/cards/public/...` routes have no auth dependency and `/shared/:token` sits outside `appGuard`. The old setup needed a carve-out in the edge's nginx; now that the backend checks auth itself, there's nothing to configure.
- **Also dropped**: the `/design` page (each app now has its own look), the service worker (the web manifest stays, so it can still be installed, as with workout), the local-user scripts (`list_users.py`, `assign_owner.py`) and the one-off legacy scripts (`import_legacy_collection.py`, `convert_legacy_decks.py`, `backfill_embeddings.py`, …), which stay in the old repo.
- **Imports take the file as a JSON body** (the page reads the file), as in workout, instead of the old multipart upload: one validation path through the request schema, same file format. Refusals are 409 (a business rule: in a deck, below what decks use, deck limits) and 422 (bad input) instead of the old 400 for both.
- **Decks kept as-is, with small changes**: a deck's rows are changed and removed by their own id (`/decks/{id}/cards/{row_id}`) instead of the old `card_id`-or-`catalog_id` + `variant_type` query; draft lines in a deck file keep their print (the old import set them all to `standard`) and are range-checked against that print; repeated cards in a deck file add up (the old import failed on them); a draft created with a paste that matches nothing is refused (422) instead of created empty; the converter's `entries` are in the user's language (its text stays English). The explicit `language` picker of the combined draft export and the missing-cards exports is kept (default English). The combat deck picker (`/decks/combat-options`) moves to 6.5 with combats.
- **Combats, purchases, shopping lists, shares kept as-is, with small changes**: combat delete-all only removes the combats the user played (an admin still wipes every combat), instead of the old wipe of the whole shared log by anyone; editing and deleting one combat stays open to any cards user (it's a shared log). Players, pickers and imports only take users with the `cards` app (grant or admin) instead of anyone who ever opened the app. Editing a combat refuses a phantom deck too (the old edit didn't check), and a side whose deck was deleted can be edited without picking a new deck. Combat responses and the player picker show pseudos only, no emails (the export still carries emails, for matching); the deck picker labels owners by pseudo (always set now). Snapshot cards are shown in the user's language by matching their `image_path` to the catalog; the stored snapshot stays English. Shopping list cards return `name` in the user's language plus `name_en`/`name_fr` for the page's own toggle; creating a list with a decklist that matches nothing is refused (422) instead of creating it empty, like drafts. The public share image routes send `Cache-Control: private, max-age=300` instead of the old `no-store`: a share page's thumbnail grid is otherwise refetched on every visit, and a revoked link still stops showing its images within 5 minutes (unlike `/images/`, cached a year).
- **Catalog management kept as-is, with small changes**: the refresh steps (HTML import, TCGdex details, scans, thumbnails, set logos/symbols, variant badges), the job progress shape, the metadata and image archive formats and the old file layout are the old app's. The changes:
  - **Dependencies**: Pillow (thumbnails) is new. The saved HTML is parsed with the standard library's `html.parser` instead of BeautifulSoup (+ lxml for the badges): the fragments only need their `<img>` attributes, the first `<h1>` and the text, and the output was checked identical to the old parser on all 50 sets (9,136 cards). Badge detection looks for each badge URL in the raw HTML.
  - **One catalog job at a time** (a refresh step, the full refresh, the metadata import or the images import; another one is 409), instead of letting the download steps overlap. The admin waits a little longer; nothing can race on the catalog rows. Start routes answer 202.
  - **Images import as the raw zip body**, not multipart (it would add `python-multipart`) nor JSON (a 2 GB zip doesn't fit one): the page sends the file as the body, the backend streams it to a temporary file inside `CARDS_DATA_DIR` (same disk as the result, never in memory or `/tmp`), then a background job restores the selected entries straight into place and links pending catalog scans, polled like the refresh. The old import extracted the whole archive into a temp folder first and ran inside the request. Entries that would leave the folder are skipped. nginx gives that one route a 4 GB body limit with request buffering off.
  - **Images export streamed** as the zip is written (stored entries on a write-only sink, ZIP64 when needed), instead of being built into a temp file first; nginx passes it on unbuffered.
  - **Refusals**: the metadata import takes the file as a JSON body; a bad file (now also an empty one) is 422, and an image path owned by another card, an ambiguous existing card or another running job is 409, instead of the old 400 for all. Stats need an admin (any user before).
  - **Basic Energy names**: `Basic <X> Energy` is stored as `<X> Energy`, as data-model.md says (the old DATA import had stopped doing it, contrary to its own docs); the `Energies` set's dated names are kept.
  - A renumbered card's `__pending__` placeholder always follows its new number (the old import only renamed the legacy placeholder form).
  - Dropped with Card Scan: clearing embeddings when a scan path changes and the images import's CLIP phase (its steps are now upload, restore, link).
- **Frontend**: all pages are standalone and lazy loaded, with signal state (including the persisted add-to-collection/add-to-deck queues) and OnPush views. HTTP Observables and debounced event streams remain I/O, with no RxJS state store or zone.js. The shared language switch saves the account, then recreates the active page to refetch server-localized card names/images; ordinary same-URL navigation stays ignored so draft-modal browser history still works. All API paths use the new mapping, including deck-row ids and public token-scoped scans. Shopping-list language toggles use `name_en`/`name_fr`; deleted-deck combats remain editable, and Gestion counts only the combats the current user can bulk-delete. `readJson`, `downloadBlob` and `httpErrorMessage` are shared helpers (workout now re-exports the same JSON reader). Catalog images use the XHR backend for upload progress, a raw `application/zip` body and status polling after 202; export uses an anchor, so the browser streams the multi-GB archive. Running full/step/import jobs are rediscovered on entry. The Poké Ball manifest and icons are kept, with no service worker. Styling is neutral and token-based until 6.8.
- **Kept as-is**: the data model and business rules (catalog + variants, per-variant ownership, normal/phantom decks, drafts, combats shared between users, purchases, shopping lists, shares), the JSON export formats (old files import unchanged) and the FR/EN UI.

## Cutover tooling: backups, cert hook, CI (2026-10-18)

What the cutover needed from the repo, ported from the old repos and adapted to one stack:
- **Backups**: one `pg_dump -Fc` of the `website` database a week (host crontab, `infra/backups/backup.sh`), the newest 7 kept on the VPS, the new one emailed through `msmtp` while under 20 MB, as `vps-edge` did. Chosen over disk only (no copy off the box) and an S3 bucket (an account and credentials for a small dump; ideas.md). The custom format replaces three plain SQL dumps: it's compressed and lets `pg_restore -n` take one schema out of the whole-database dump. The old script's embedding-column workaround is gone with Card Scan. The `cards_data` images aren't covered: the catalog image export zip is their copy.
- **Restore**: the whole database (`all`) or one app schema, chosen over whole-database only, so a bad cards import can be undone without rolling back everybody's workouts. A schema is dropped, recreated and reloaded in one transaction (`pg_restore -n` doesn't create the schema). `core` only comes back with `all`, since every app schema has FKs into `core.users`. Same type-the-name confirmation and backend stop as the old script.
- **Cert hook in the repo**: `infra/certbot/deploy-hook.sh`, installed as a symlink in certbot's `renewal-hooks/deploy/`, instead of a script written by hand on the box as with `vps-edge`. One cert path (`infra/ssl/alanbignon.com/`) instead of one copy per domain.
- **CI**: one GitHub Actions workflow (`ci.yml`): ruff + `black --check`, pytest against a Postgres 18 service on the dev port (so the tests need no change), every frontend project's tests; a push to `main` deploys over SSH (`git pull --ff-only && make prod`, then `docker image prune -f`) only when all three pass. Chosen over the old repos' setup (lint only, deploy on every push regardless) and over gating on backend tests only: a few more minutes per push for not shipping a broken frontend. The image is still built on the VPS, as the old repos did (building in CI is in ideas.md if memory runs short). Same secret names as the old repos.
- **No redirect for the old workout URLs**: workout moves from `alanbignon.com` to `workout.alanbignon.com` and the apex becomes the portfolio. Its paths are not redirected; its few users get the new address (ideas.md).


## Light/dark switch in every app, one choice saved on the account (2026-10-18)

- **Every app gets both themes**, chosen over a switch only in the two apps that already had a dark mode (workout, cards). The missing ones were derived from each app's palette rather than mocked first: a light portfolio (off-white paper, ink text, a darker lime readable on white), a dark media (ink-brown "library at night", cream text, lighter oxblood/teal/ochre), and a light and dark auth (light: the cobalt grid as before; dark: a near-black navy grid, same white-card/black-border/yellow-button brutalism, the card turned dark grey).
- **Three states**: System (default), Light, Dark. `System` follows `prefers-color-scheme`, as workout and cards did, so nothing changes for whoever never touches it.
- **One choice for every app**, saved in two places: a `theme` cookie on `.alanbignon.com` (host-only `localhost` in dev, where cookies aren't scoped by port anyway), and `core.users.theme` when logged in, like the language. Chosen over the cookie alone so the choice follows the account to another device, and over per-site `localStorage` (what the language uses logged out), which can't be shared across subdomains. The cookie is not HttpOnly: an inline script in each `index.html` reads it before Angular boots and sets `data-theme` on `<html>`, so the page never flashes the wrong theme. A logged-in user's saved theme wins over the cookie and rewrites it.
- **CSS**: each app keeps its default tokens on `:root` (light; dark for portfolio), and redefines them for the other theme under `:root[data-theme=…]` and under the matching `prefers-color-scheme` query guarded by `:not([data-theme=…])`. No class-based theme library. Auth's black was split into text, border and shadow tokens so its dark card keeps black shadows with off-white outlines.
- **Where**: an icon button in `ab-header`, next to the FR/EN switch, cycling System → Light → Dark (monitor/sun/moon icons, the label says the current one). Auth, which has no header, gets a picker on its account page next to the language one, as for the language.

## Safety worker for the old apps' service workers (2026-10-18)

The old `pokemon_cards` and `workout` apps registered an Angular service worker (`/ngsw-worker.js`) on `cards.` and `workout.alanbignon.com`. The new apps have none, and nothing removed the old one. Browsers that had used the old app kept serving its cached shell, which still checked the old `auth_token` cookie. It saw the user as logged out and sent them to the auth login page, which saw them logged in and sent them straight back: an endless redirect, in prod only. The old worker never removes itself: Angular's worker unregisters when `/ngsw.json` answers 404, but the edge's `index.html` fallback answers 200.

Fixed by serving a safety worker at `/ngsw-worker.js` on those two hosts, as Angular's docs recommend, over a `/ngsw.json` → 404 rule in nginx. A browser re-fetches the worker script on navigation even while the old worker is in control. The new script installs at once: it deletes the `ngsw:*` caches, unregisters itself and reloads the open tabs. Waiting on the old worker's own update check would take longer. The script is Angular's `safety-worker.js` plus that reload, kept in `projects/shared/public/` and copied into both builds through `angular.json` `assets` (one copy). The edge serves it `no-cache`. It can be dropped once old visitors are unlikely to come back. A real service worker for either app (ideas.md) would replace it under the same name.

## Cards: purchase lists from Cardmarket orders (2026-10-19)

- **What**: a "Liste d'achat" per bought Cardmarket order, filled by uploading the order page's article table saved as HTML, whose cards count as owned in the missing views until the package is marked received, which adds them to the collection.
- **One list per order**, over a single pooled list: packages arrive separately, and each one is checked and received on its own.
- **Parsed on the backend** from the `<tr data-article-id>` rows (set code + number from the card name, `Reverse Holo` or, on the French site, `Reverse` → `reverse`), over a client-side parse: testable with pytest next to the converter's matching, and the frontend only sends the file's text. Matching by set code + number, over the converter's name matching: Cardmarket's codes (`SVI`, `PAL`, …) are the catalog's, so it's exact. Other prints (ball reverses, stamps) aren't recognised; they are fixed by hand on the list.
- **The What I Paid total is entered at import**, pre-filled with Σ article prices: the table has neither shipping nor the order total.
- **Incoming counts as owned only where something is missing** (set page filter, missing exports, `/missing`), with a toggle; completion, the collection and decks stay on real ownership, so nothing claims cards that haven't arrived.
- **Received lists are kept** (read-only) as a record of what came in, over deleting them on receipt.

## Cards: shopping lists folded into purchase lists (2026-10-19)
